# Arrival lagoon replaces the starter river

The arrival hub is re-authored as an irregular, terrain-backed lagoon with a configured volcano, south-bank settlement, and inward-facing dock fan. The generic river generator is bypassed whenever the lagoon feature is present, while `River = true` remains in configuration for callers that still treat it as a channel contract. The lobby source is not part of the tracked diff, so the boarding scene itself was not unintentionally changed. **Watch for:** **confirmed** the lagoon docks’ raft-collision envelopes include the spawn point, and **confirmed** the settlement is built below the new terrain surface; both block a playable arrival flow.

## High-level view

The lagoon generator replaces the generic terrain path wholesale, then carves four overlapping water rectangles after placing the land shelf and ridge/volcano geometry. **Confirmed:** no flat settlement pad is created at the configured settlement location, while the village builder continues to author gameplay objects at the old global build height.

The dock fan correctly changes visual orientation toward the protected water, but it retains the generic dock collision padding. **Confirmed:** the middle pier’s expanded collision rectangle reaches six studs past the lagoon center, where an `Offset = Vector3.new(0, 0, 0)` arrival hub is co-located with the starter-base origin.

**Confirmed:** retaining `River = true` is not compatible with the existing runtime representation: lagoon planning deliberately omits `features.river`, so no `record.river` is published and no river corridor is carved.

**Likely:** the ocean streamer overwrites terrain below the water surface and the new safe-harbor exception no longer restores the hub’s custom submerged shelf after a stream refresh.

## Dock collision covers the arrival spawn

**Confirmed.** `planIslandFeatures` changes all three arrival docks to lagoon targets, and `decorateShore` builds each one from `lagoon.radius + 20` to `lagoon.radius * 0.18`. With the configured 780×610 lagoon, `radius` is 256.2, so the center pier runs from 276.2 to 46.1 studs and is centered about 161 studs north of the lagoon center. `buildDock` registers that entire 230-stud deck as a raft collider; `segmentHitsDock` expands its long axis by `Config.Islands.RaftCollisionPad` (52 studs). The resulting blocked interval reaches from roughly -6 to 328 studs along the pier, containing the hub center.

`arrival_hub` has zero offset and is co-located with the starter-world origin, so the starting raft begins inside the center pier’s expanded collision volume. `collideRaft` rejects any attempted helm movement whose segment starts or enters that volume. Leave a clear radius for the 64-stud raft before the visual dock fan can ship, for example by beginning collider coverage outside the spawn basin or trimming the landward collision section.

## Settlement placement no longer matches the terrain build height

**Confirmed.** The new settlement center is `(0, 0, 410)` relative to the hub, but `generateLagoonHubTerrain` has no settlement foundation. That point lies inside the tile centered at `(260, 275)`, whose terrain surface is `topY + 9`; the overlapping northern tile also rises to `topY + 6`. `VillageBuilder.build` receives `topY` unchanged and emits the campfire, house floors, fences, streets, merchant, loot, and villager home positions at that height or only 2.5 studs above it.

The central campfire and several props are buried, and NPC roots can be spawned inside solid terrain. The retained river flag also still activates the village builder’s river-bank house displacement, even though this hub has no `features.river` or carved channel. Build a flat, dry pad at the settlement offset with a top exactly at `topY`, or make the village API resolve terrain heights and explicitly disable river layout logic for lagoon hubs.

## Lagoon feature suppresses the published river contract

**Confirmed.** The configuration says the 440-stud river is retained as a compatibility marker, but `planIslandFeatures` only creates `features.river` when `entry.River == true and not features.lagoon`. `buildFlatIsland` only assigns `record.river` from that omitted feature, while `decorateArrivalHub` returns early for the lagoon. The hub consequently has neither a sea-to-sea carved river nor the `IslandRecord.river` geometry described by the service API and existing comments.

Either publish a lagoon navigation/collision descriptor through the existing river interface where consumers require it, or introduce an explicit harbor feature and migrate the contract, including the village layout branch that still interprets `River` as a real waterway.

## Safe-harbor exception leaves streamed terrain unrepaired

**Likely.** `OceanTerrainService.clearChunk` and `fillChunk` replace each active chunk’s full below-surface volume with Air or Water. The normal recovery path calls `IslandService.paintTerrain`, but the change skips every `safeHarbor` island to avoid repainting a circular sand cylinder. After a chunk is recycled, the hub’s below-water sand tiles are never restored.

This makes shoreline and submerged geometry depend on stream history. Repaint the irregular lagoon shelf idempotently after ocean writes, preserving the custom outline without reverting to the old cylinder.

## Arrival path lacks runnable regression coverage

**Confirmed.** The only added test artifact is an untracked `IslandShape.spec.luau`, but the runtime change never imports `IslandShape`; the lagoon is generated directly in `IslandService`. Running `lune run tests/IslandShape.spec.luau` fails before assertions with `IslandShape:132: attempt to perform arithmetic (mul) on nil and number`. It cannot detect the dock overlap, settlement elevation mismatch, river descriptor removal, or stream repaint behavior.

Add a focused arrival-hub test or Studio integration check that asserts a starter-raft-sized collision-free basin, dry/level settlement spawn positions, published navigation metadata, and persistence of custom terrain after an ocean chunk refresh. Track only the test code that exercises the shipping path; the untracked `IslandShape` module and its failing test are otherwise unrelated to this implementation.
